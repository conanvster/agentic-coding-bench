# DECISIONS — неоднозначності ТЗ і рішення

Формат: Питання → Рішення → Чому.

- Текст на макетах спотворений («Оаиг приимующеєв», ціни в `$`) → текст, валюта (₴) і перелік функцій — з `structure.txt`; з макетів — лише сітка, кольори, типографіка → ТЗ §0: текстовий опис перемагає макет.
- Вкладка «Retailing / Quick View» на макеті каталогу → «Retailing» — артефакт генерації, окремої вкладки немає; «Quick View» — кнопка на картці, що відкриває модальне вікно (F-031) → у .txt і ТЗ §4.3 Quick View описано як модальне вікно картки, вкладок каталогу немає.
- Діапазону знижок -50…-70% у .txt немає → додано (F-035) → без нього шкала знижок має розрив; ТЗ §4.3 вимагає це зафіксувати.
- Межа «AAA-релізи» → поточна ціна ≥ 1500 ₴ (150000 копійок) → ТЗ §4.3 дає цю межу; ціна — поточна (акційна), як і для решти фільтрів.
- На макеті «Геймерський кешбек» показано двічі → 4 різні переваги: Миттєвий доступ, 100% ліцензія, Геймерський кешбек, Підтримка 24/7 → ТЗ §4.2.3 прямо називає це помилкою макета.
- Гроші → integer у копійках у БД і API, форматування `899 ₴` лише на клієнті → ТЗ §4: числа з рухомою комою для грошей заборонені.
- Порт вебзастосунку → `WEB_PORT` у `.env`, типово 8088; nginx у контейнері слухає 8080 (non-root не може < 1024) → ТЗ §3, §6.
- Postgres назовні → не публікується, лише мережа compose → ТЗ §3.
- Тестова БД → окремий сервіс `db-test` на tmpfs у `docker-compose.test.yml` → ТЗ §6: тести на окремій БД, швидкий старт і чистий стан щоразу.
- «Найновіша» гра для golden path → визначається на етапі 3 разом із сідом (фіксовані дати) і записується сюди → ТЗ §1: має бути детермінованою.
